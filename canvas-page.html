👨‍💻 Code-Together 19: Shortest Path & MST

🎯 Overview

An in-class code-together activity extending the adjacency-list graph from CT18 to weighted graphs, then implementing Dijkstra's algorithm for shortest paths. Students store edges as Edge structs (destination + weight), implement add_edge for the weighted undirected case, and then build Dijkstra's step by step: distance map, min-heap priority queue, stale-entry skip, and edge relaxation. Prim's MST algorithm is provided as an instructor-led walkthrough (CCD 2.12 is lecture-only) so students see the same priority-queue pattern solving a different problem.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Explain why BFS doesn't work on weighted graphs and why weighted shortest path needs a different algorithm
  • Implement add_edge for a weighted undirected adjacency list (push Edge{to, weight} on both sides)
  • Implement Dijkstra's algorithm using a std::priority_queue as a min-heap via std::greater<Pair>
  • Explain the relaxation step -- when dist[u] + edge.weight < dist[v], update dist[v] and push a new heap entry
  • Explain why stale heap entries occur (no decrease-key) and why if (d > dist[u]) continue; is the standard fix
  • Read Prim's MST walkthrough and explain how the same priority-queue pattern minimizes total edge weight instead of source distance

📝 What You’ll Do

Open WeightedGraph.cpp. The constructor, queries, and add_vertex are already implemented -- identical to CT18's Graph. Your three tasks are add_edge (Section 2), dijkstra (Section 4), and reading through the provided prims_mst (Section 5) while the instructor walks it in class. After each TODO, run main.cpp to verify the city-map demo output, then re-run the test suite to watch the Dijkstra points come in.

📚 Teaching Order

Work through the files in the order main.cpp calls them:

1. WeightedGraph.h — Review the weighted interface

Section What You’ll Learn
Edge struct destination vertex plus integer weight; replaces the bare string neighbor from CT18
adj_list_ now unordered_map<string, vector<Edge>> so each neighbor carries its edge weight
dijkstra signature takes a source vertex, returns an unordered_map<string, int> of shortest distances
prims_mst signature takes a start vertex, returns a pair of (MST edges as (from,to,weight) tuples, total weight)

2. WeightedGraph.cpp — Two student TODOs + one provided walkthrough

Section What You’ll Learn
Section 2: add_edge ensure both vertices exist, push Edge{to, weight} into from's list and Edge{from, weight} into to's list (undirected)
Section 4: dijkstra full 10-step implementation: dist map, guard, source seed, type alias, min-heap with std::greater, main loop, stale-entry skip, relaxation

3. main.cpp — City map demo (3 sections)

Section What You’ll Learn
Section 1: Build weighted graph SLC, Ogden, Provo, Logan with 5 edges; print() shows the adjacency list with weights
Section 2: Dijkstra from SLC verify SLC=0, Ogden=4, Logan=3, Provo=5 (SLC->Logan->Provo = 3+2 beats direct SLC->Provo = 6)
Section 3: Prim's MST from SLC verify SLC-Logan(3), Logan-Provo(2), SLC-Ogden(4), total weight 9

🔧 Troubleshooting

CMake does not configure automatically

  1. Check the bottom-left corner of VS Code reads Dev Container. If it does not, press Ctrl+Shift+P and run Dev Containers: Reopen in Container
  2. Make sure Docker Desktop is running, then reopen the folder
  3. Delete the build/ folder and run cmake -B build again
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In the container terminal, run ./build/ct18-shortest-path-mst
  2. Or press Ctrl+Shift+P and run CMake: Run Without Debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder.
